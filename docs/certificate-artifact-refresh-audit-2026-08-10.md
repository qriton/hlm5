## Outcome

The packaged certificate engine is hardened, but the six published
certificate/dosing artifact families are not yet publication-ready evidence for
that hardened implementation.

Three independent gaps bind:

1. every producer now uses `EPS = 0.0`, but all six still construct the
   certificate tensors with `.float()` arithmetic while release text describes
   float64 certificate arithmetic;
2. none of the result contracts binds the epsilon, arithmetic dtype, producer
   hash, and model/data hashes together; and
3. the CounterFact producer resumes existing rows by `case_id` without checking
   any certificate contract, so a nominal rerun would silently retain the old
   rows.

The existing `scripts/verify_artifacts.py` also references none of the seven
primary certificate payload files. It verifies selected legacy headline JSONs,
not every quantitative artifact cited by the paper.

## Required repair before measurement

Each producer must emit a `certificate_contract` containing at least:

- `eps: 0.0`;
- `arithmetic_dtype: "float64"`;
- producer repository path and SHA-256;
- checkpoint and tokenizer SHA-256 for the frozen HLM5 trunk; or pinned model
  revision and data SHA-256 for CounterFact; and
- for a resumable JSONL, the row-file SHA-256 and exact contract checked before
  accepting any existing row.

The implementation must perform the affine certificate arithmetic in float64,
not merely label a float32 result as hardened. Model forward passes may remain
in their native dtype; cast the hidden, head, value, slopes, ratios, bounds, and
dosing objective at the certificate boundary.
